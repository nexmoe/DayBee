# 声纹分批实施：独立审核记录

日期：2026-10-12。Grok 4.7 子代理分批实现，主代理设计接口、审核并独立复测。本次计划内功能已集成；识别目标仍有未达标项，不能称为所有场景精度达标。代码留在工作区，未提交或推送。

后续用户反馈暴露了“声纹置信变化直接切断转写”的体验退化，已按 [发言连续性修订](voiceprint-utterance-continuity.md) 改为每次 VAD 完整解码一次。下文原始性能与分段说明是修订前的记录；声纹区间统计不等于整句徽章准确率。

## 落实范围

| 阶段 | 已集成的功能 | 效果或范围限制 |
| --- | --- | --- |
| P0 | 原始窗口打分、公开语料评测、已有完成录音的本地导出、人工真值 sidecar | 真实房间数据尚未积累 |
| P1 | 独立于系统录音保存的内存播放参考、缺口与 epoch、降级提示、500 条系统临时池 | 到达时间近似，无硬件 PTS；真实权限链路未测 |
| P2 | 三态迟滞、身份分段、串行 ASR、边界保护、受限上下文放宽 | 窗口边界较粗；重叠不能分离成两条说话人轨道 |
| P3 | v3 档案、固定 cohort/AS-norm、个人校准、设备/AEC、SNR/播放暂停/完整回滚 | 部分阈值贴近归一化下界；未证明归一化改善准确率 |
| P4 | ERes2NetV2 选型、默认关闭的 32 条学习池及开关/计数/清除、线程/ASR/内存测量 | 学习池会增长，本次未测得召回或误接受收益 |

可选的 pyannote/sherpa 离线说话人聚类没有引入；当前生产功能是本人身份切分，不提供说话人分离。多设备独立声纹、加密保存录入 PCM、后台自动重算也不在本次实现范围。录入仍只在内存保留音频。

## 输入与隔离

- 模型：`3dspeaker_speech_eres2netv2_sv_zh-cn_16k-common.onnx`，192 维，SHA-256 `bf1a75b9930474cf3389ef415e6e5d38ca96fea4a3a00f7e301d080a58ee2239`。
- 公开 AISHELL-3：16 kHz 单声道，13 人、353 句、744.23 秒。固定 cohort 是 9 人各 32 个窗口，共 288 条向量，不能称为 288 位说话人。
- 留出 SSB0544、SSB0700、SSB0693、SSB0434 的全部语句不进入 cohort。每人录入与测试按整句分离；生产评测录入三组各使用 8 秒 raw PCM，没有以 VAD 取得净语音。
- “留出”仅指本批 cohort 与个人录入。历史模型横评和 `0.537` 选择使用过同套 13 人语料；本批没有重新调阈值，仍不能视为完全未见数据的无偏准确率。
- 没有使用用户麦克风、私人录音或真实声纹。桌面验收使用临时隔离 store 与测试引擎，真实模型测试只读公开音频。没有验证实际房间或 ScreenCaptureKit 授权链路。
- AISHELL-3 的 Apache-2.0 LICENSE/NOTICE 已嵌入并随原生包附带；公开 WAV/PCM 哈希与 cohort 再生成此前已核对。

## 界面清晰度修订

用户指出首次录入与“学习我的声音”命名重复，0/32 暴露内部容量、评测导出占据日常设置。修订后只保留一个声纹管理区，明确说明转写会将本人发言标记为「我」。可选功能改为“录音中持续适应（实验性）”，放在默认折叠的高级选项中；说明关闭也能使用声纹。内部计数仅用于判断是否可以重置，不显示容量或进度。已有开启偏好不重置，折叠摘要仍显示开启状态。

诊断导出移至转写设置底部的“识别诊断”，默认折叠，解释用于排查标注问题。选项使用简短本地日期和最多 32 码位预览；录音/转写忙碌时直接说明为何不能导出。运行参考提示放回声纹区域内，停止录音后隐藏过期参考状态，设备不匹配仍保留。

主代理检查了中英文 1000px/480px 截图；四个布局用例均无横向溢出。真实设置、重置和导出 RPC 回归继续通过，最终共 25 项端到端用例通过；typecheck、61 项 Vitest、重新构建及包验证也通过。此轮只改变界面组织与文案，识别算法和下文统计没有改变。

## 生产判定结果

完整分类统计和每次试验见 [运行时统计](voiceprint-runtime-eval.json)。以下按样本时长加权，不把 uncertain 从本人漏接受分母删除；开启与关闭学习的分类结果相同。

| 场景 | 本人召回 | 非本人误接受 | 不确定占比 |
| --- | --- | --- | --- |
| 干净本人 | 94.82% | 不适用 | 3.45% |
| 他人 | 不适用 | 0% | 0% |
| 本人视频副本、80ms 延迟混响 | 不适用 | 0% | 0% |
| 本人和系统声音重叠 | 50.89% 混合区本人占比 | 不与纯他人 FAR 混算 | 17.89% |
| 本人—他人—本人，各 4 秒 | 85.42% | 0% | 8.33% |
| 合成 15 dB 噪声 | 91.37% | 不适用 | 3.45% |
| 设备或 AEC 不匹配 | 不贴本人 | 不适用 | 100% |
| 0.5 秒本人 | 0% | 不适用 | 100% |
| 1 / 1.5 / 2.5 秒本人 | 100% | 不适用 | 0% |

四人中三人能组成合格录入。SSB0700 留出 8.04 秒后，三组原时长为 11.91 / 7.43 / 8.83 秒，其中一组不足 8 秒，按数据不足拒绝；本次拒绝比例 25%，不能当作一般用户录入拒绝率。三个成功档案的 low 约 -19.999998、high 约 -19.699999；大量 cohort 负例由原始底线固定成 -20，所以不能证明个人归一化有额外识别收益。

独立的早期 4–5 秒最小 probe 中，同一 SSB0700 是因 FA 界高于 FR 界而被拒绝；那是另一套录入拆分，不与上面的原始时长不足混为一谈。其余三人的最小本人/他人/本人视频 probe 通过。

边界修订前，4+4+4 秒拼接的他人区域误接受为 8.33%、本人召回 93.75%。审核发现窗口按起点归属使本人标记提前；现在依据相邻非本人窗口的实际 `[Start, End)` 保护交界，重叠的本人范围改为 uncertain。修订后误接受为 0%，召回降至 85.42%。没有为数据修改 `0.537`、1%、5%、0.8 或辅助上限 0.3。

六个真值边界中，三个直接边界仍提前 0.5 秒；另外三个以宽 1 秒的 uncertain 区间覆盖真值，没有精确边界。报告保留精确边界缺失 3/6，未检出 0；宽区间不记为零偏差，也不进入直接边界误差平均。只统计三个直接边界的平均绝对偏差是 0.5 秒，不能当作六个边界的完整平均误差。

学习开启后最多写入 11 条样本，系统池最多 17 条。所有场景召回/FAR 差值均为 0，未测到识别提升。公开朗读、固定种子合成噪声与混响不能替代本人/旁人/扬声器的真实房间验证。拼接召回低于 90%，重叠识别有限，因此原先“所有场景目标达到”的验收条件没有满足。

## 性能与内存

独立测量在 Apple M5 Pro / 64 GiB、darwin-arm64、Go 1.27.1 上完成，进程用时 83.02 秒。统计和全部原始轮次见 [性能统计](voiceprint-runtime-performance.json)。使用固定 Qwen3 ASR 0.6B int8、同一生产 recognizer，每种模式先预热一次，再测三次，每轮先清空学习池及系统池；全部输入连续覆盖并逐段 Decode。不测生产 ASR 队列等待。

1.5 秒窗口另用同一公开片段、各预热三次后测 20 次；生产仍使用两线程。

| 声纹线程 | 均值 | p50 | p95 |
| --- | --- | --- | --- |
| 1 | 37.89 ms | 37.75 ms | 39.28 ms |
| 2 | 33.83 ms | 34.27 ms | 35.02 ms |

下表均为三次均值。学习关闭/开启列依次为声纹时间、Decode 次数、总时间；总时间包含声纹及全部解码。

| 片段与参考 | 时长 | 仅 ASR | 学习关闭 | 学习开启 | 开启后池数 |
| --- | --- | --- | --- | --- | --- |
| 中文、完整静音参考 | 11.38s | 1706ms | 616ms / 1 / 2336ms | 608ms / 1 / 2304ms | 0 |
| 本人—他人—本人、静音参考 | 12s | 997ms | 682ms / 4 / 1829ms | 689ms / 4 / 1839ms | 9 |
| 本人视频、原始参考 | 8.86s | 753ms | 980ms / 1 / 1733ms | 1087ms / 1 / 2204ms | 0 |
| 干净本人、静音参考 | 8.86s | 1002ms | 541ms / 1 / 1467ms | 495ms / 1 / 1369ms | 9 |

关闭学习的总 RTF 依次约 0.205、0.152、0.196、0.166。拼接比旧报告多一次 Decode，是保留 guard 的 uncertain 区间所致，没有丢弃音频以缩短时间。原始参考需要回声嵌入，声纹耗时高于静音参考。四种模式固定顺序、每种仅三次，后半程计时波动明显；开启学习在一些模式更快、另一些更慢，不能归因为学习加速或成本。两个场景池仍为 0，只能说明本次保守门槛未触发。注册原组可用时长 14.86 / 13.82 / 12.79 秒，实际各嵌入 8 秒；测试 8.86 秒整句留出，没有混入注册。

单独编译测试二进制后用 macOS `/usr/bin/time -l` 测完整推理进程，最大 RSS 为 **3,293,364,224 字节（3.07 GiB）**，peak memory footprint 为 3,102,166,808 字节。它包含 Qwen ASR、ERes2NetV2、ONNX 和测试进程，不能当作声纹独占或增量内存；Go 编译器不在测量进程内。GC 后 Go heap alloc 为 939,896 字节、inuse 为 1,630,208 字节、sys 为 37,126,144 字节，不能替代原生 RSS。没有测长期泄漏或生产队列积压。

## 复现

在 `apps/desktop` 使用 Go 1.27.1：

```sh
go test -race -count=1 -timeout 12m ./...
go vet ./...
EVE_VOICEPRINT_PIPELINE_MODEL=/path/to/model.onnx \
EVE_VOICEPRINT_PIPELINE_WAV=/path/to/aishell3-wav \
EVE_VOICEPRINT_COHORT_WAV=/path/to/aishell3-wav \
EVE_VOICEPRINT_RUNTIME_OUT=/tmp/voiceprint-runtime.json \
go test -race -count=1 -timeout 12m ./internal/voiceprint/
bun run typecheck
bun run test
node scripts/desktop.mjs build
node scripts/verify-package.mjs
bunx --no-install playwright test --config playwright.config.ts \
  e2e/voiceprint.spec.ts e2e/voiceprint-guidance.spec.ts \
  e2e/voiceprint-quality.spec.ts e2e/voiceprint-export.spec.ts \
  e2e/voiceprint-export-rpc.spec.ts e2e/voiceprint-adaptation.spec.ts \
  e2e/voiceprint-settings-clarity.spec.ts e2e/system-audio.spec.ts e2e/echo-cancellation.spec.ts
```

性能另设置 `EVE_TEST_MODEL_DIR`（固定 Qwen3 ASR）与 `EVE_TEST_AUDIO_DIR`（含 chinese.wav），运行 `TestNativeRuntimePerformance`。模型及音频由操作者自行置于外部目录，不随仓库提交。其余本次实现行为见 [声纹](../subsystem/voiceprint.md) 与 [分批记录](../superpowers/voiceprint-implementation-plan.md)。
